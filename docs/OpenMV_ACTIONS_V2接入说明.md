# main.py 对接 ACTIONS_V2

最新修改：初始化完成后发送一次 `start\r\n`，由SEND_START_ON_BOOT控制。用户提供的新版动作说明未列出start，STM32需另外实现路线启动；发送成功不代表底盘已执行。不会自动发送ZERO或在STM32重启后重发start。

右90°到左90°的相对左180°请求现拆为YAW_HOME、等待DONE、YAW_L90、等待DONE，两步完成才确认原任务事件。左90°到右90°仍直接使用YAW_R180。必须事先手动摆正并显式ZERO，让OpenMV桥接层收到其DONE并记录参考。旧说明中该左180°被阻塞的描述由此更新替代。直行/平移/到站协议仍需实现。

激光控制改为P5，高开低关；UART1仍是P0 RX接PD8 TX，P1 TX接PD9 RX。P5不能同时作为UART3 RX使用，且应确认转接板UART3转换电路没有驱动这条线。激光瞄准标定开关保留，换引脚不代表完成瞄准标定。

默认STM32_PROTOCOL="ACTIONS_V2"，不向这套固件发送VIS/VEVT/VCMD帧。需要回到原视觉协议时选择"VISION_V3"，两种协议不能混用。

ActionsLink.request_action(command)支持文档中的命令，发送实际CRLF。运动使用递增编号，等待匹配编号的DONE；BUSY仅代表启动，ERROR保留任务事件并停止自动派发。超过20秒未收到完成回复发送STOP，清除本地yaw参考。不自动重发运动，也不自动ZERO。

运行时ACTION_LINK和MISSION为主程序对象。辅助调试或以后路线调度代码可调用：

```python
# 必须先手动将水平云台摆到正前方，并确认机构空闲。
ACTION_LINK.request_action("ZERO")
# 收到0 DONE后才有有效本地yaw参考。
# 手动/调度器确认底盘在二维码位置停稳后：
MISSION.arrive(1)
# 查询状态不移动机构：
ACTION_LINK.request_action("STATUS")
```

这些是后续调度代码的Python接口，不是现有STM32的串口指令，也不是运行中IDE终端可直接执行的交互命令。默认启动仍只做TRACK视觉，不会自行开始路线。仅在安全停稳、对应请求事件已被实际处理后，调度代码才能确认事件并调用下一到达码；不要用固定延时模拟底盘到站。

可明确对应的水平动作事件18/6/7/5由桥接层尝试发送；内部记录yaw的前/左/右位置。正前方到左用YAW_L90，正前方到右用YAW_R90，左右回正用YAW_HOME，左到右用YAW_R180。动作DONE后才确认原事件。首次两段路线的水平转向完成可调用71/73/75；拐角还需底盘转向，因此水平DONE不能代替底盘到站。

限制：文档未提供直行、平移、视觉纠偏、到站输入或颜色判定结果接收接口；因此现有STM32固件不能完成main.py整条自动比赛路线。二维码完成、行驶放行、夹取后返回第二球位等事件保留在OpenMV本地，打印LOCAL mission event，等待后续路线调度接口。底盘左右转90°可以显式request_action，但默认不自动接续底盘路线。

文档未提供“右90°直接到左90°”的单条命令。此动作以及未知yaw参考不会被猜测执行，而是打印YAW blocked。外部直接操作yaw/STOP/ZERO会改变机构状态，不能与桥接层控制混用；若STM32重启、报错或参考失效，重新手动摆正并显式ZERO。

未修改STM32代码。完成的是激光P5与已存在动作协议的接入，不是完整底盘路线固件。已通过本地模拟的ZERO、编号BUSY/DONE、回正映射及ERROR处理，尚未上板验证。
