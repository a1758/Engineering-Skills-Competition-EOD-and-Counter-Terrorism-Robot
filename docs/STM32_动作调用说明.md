# STM32 动作调用说明（ACTIONS_V2，2026-10-07）

## 2026-10-11 小球流程更新

独立小球联调以同目录《独立小球夹取联调说明.md》为准，替代下面2026-10-10提出的带编号小球扩展方案。当前握手为 ball → finishball → down → wrong/right → grab → none/one/two → home → finishhome。yaw左90°后开始；RACK累计-2600、LIFT累计-1300后识别；夹取后根据wrong次数回第二球位，LIFT累计+1300，再yaw右180°后释放。RACK伸出量和放球后的纠偏距离待定。

现有单次RACK/LIFT范围为±1000，累计-2600应分为-1000/-1000/-600，累计±1300分为±1000/±300，各段依次等待完成。finishhome后由路线调度切入已有视觉纠偏，慢速纠偏完成后再全速；独立小球脚本不提供轨道纠偏数据。

## 小球识别停车与固定夹取：建议新增接口（2026-10-10）

以下是待 STM32 实现的扩展约定，不是当前固件已有命令。STM32 控制底盘，OpenMV 控制识别、P7 俯仰和 P8 夹爪。建议增加仅停止底盘的 `BASE_STOP`，不要用现有 `STOP` 代替正常抓球停车：现有 STOP 会停止上装并清除 yaw 参考，影响后续动作。

建议时序：

1. STM32 的路线调度器选定球位并低速接近，给 OpenMV 发 `ball 1\r\n`（1红、2绿、3蓝）。目标颜色应来自 OpenMV 保存的二维码任务；实际比赛由 OpenMV 保留任务颜色，STM32 不需要重复选择或比较颜色。这个带颜色命令仅供独立测试。
2. OpenMV 将俯仰设为小球视角，确认目标位置后发 `101 BASE_STOP\r\n`。101 是示例递增动作编号，不发送底盘速度或转向指令。
3. STM32 回复 `101 BUSY\r\n`，取消当前接近动作和继续行驶的自动调度，调用底盘停止封装函数；保持 yaw、抬升、齿条状态和 yaw 参考。
4. STM32 根据驱动板反馈确认车轮停稳后回复 `101 DONE\r\n`。建议可配置停车阈值和连续稳定时间，初始稳定时间可用 200 ms；超时或反馈无效回复 `101 ERROR BASE_STOP_TIMEOUT\r\n` 或 `101 ERROR FEEDBACK_LOST\r\n`。不能只因停止命令已发出就返回 DONE。
5. OpenMV 只接受匹配当前编号的 DONE，随后执行固定夹取：140°张开，等待 500 ms；100°闭合，等待 1000 ms。夹取阶段不再依赖小球是否仍在画面内。
6. OpenMV 发 `BALL_GRABBED 101\r\n`。STM32 回复 `BALL_ACK 101\r\n`，记录完成；路线调度器再决定下一动作。该消息表示动作等待结束，不能证明实物已夹牢。

夹取后的返回与放球流程（无论在第1、第2还是第3个球位夹取均执行）：

1. STM32 收到 `BALL_GRABBED 101` 并回复 `BALL_ACK 101` 后，底盘统一返回第2个球位。若已经在第2个球位，则保持原位，不额外移动。
2. STM32 根据路线定位及底盘反馈确认第2个球位到达、底盘停稳；OpenMV 在返回过程中保持夹爪100°闭合，不以延时推断底盘到位。
3. STM32 调用水平 yaw 云台的右转180°封装动作，并等待完成。该动作旋转夹爪云台，不旋转底盘；水平旋转由 STM32 控制，俯仰 P7 和夹爪 P8 由 OpenMV 控制。
4. 当前 `YAW_R180` 的前提是已 ZERO 且水平云台处于左90°，动作完成到右90°。抓球前须保证这一朝向；若实物起始朝向不同，应重新定义或补充对应封装动作，不能直接套用现有 YAW_R180。
5. 只有返回第2球位停稳且水平右180°动作 DONE 后，STM32 才发送 `BALL_RELEASE 102\r\n`。102 为独立递增的放球事务编号。
6. OpenMV 执行100°闭合、等待500 ms、140°张开、等待1000 ms，回复 `BALL_RELEASED 102\r\n`；STM32 回复 `BALL_ACK 102\r\n` 后再继续路线。释放过程中底盘和水平云台保持不动。

返回失败、未停稳或 yaw 转动失败时，不发送 BALL_RELEASE，保持夹爪闭合并报告错误。水平右180°后必须保证小球处于实际放球位置；若还需俯仰对位，需实测对应 P7 角度并纳入放球动作，不以未标定角度代替。

STM32 实现要求：

- `BASE_STOP` 应能打断当前底盘动作，即使底盘忙也接受；只停止底盘，不关闭 yaw 保持控制、不清除 ZERO、不停止抬升或齿条。安全急停仍使用原 `STOP`。
- 编号去重沿用 ACTIONS_V2；相同编号重发只重发 BUSY/DONE/ERROR，不重复调度。重复完成通知应重发 BALL_ACK，不重复继续路线；旧通知不能确认新事务。
- 等待停车确认、夹取完成或放球完成时暂停路线；超时或 ERROR 保持底盘停止，禁止自动驶往下一点。
- USART3 的接收解析器区分动作命令与 BALL_GRABBED/BALL_RELEASED 通知，均使用完整 CRLF 行，支持拆包、粘包。
- `BASE_STOP` 的 DONE 只确认停车。小球是否位于可抓取位置由固定球位、停车距离和 OpenMV 的标定定位条件保证；40 mm 球直径不能直接换算为未标定的停车距离。

当前独立 OpenMV 程序仍使用 `BALL_STOP ...` / `stopped` / `BALL_OK ...` 简易握手，尚未切换到本节建议协议。STM32 实现本节后，两端应统一改成上述带编号接口，不能混用两套回复。

工程：D:/stm32project/counter。默认 Debug/Release 都编译同一套动作固件，不再切换上装测试、BMI 采集或自动路线模式。上电不自动运动；USART3 收到完整命令后才执行动作。OpenMV 代码由其他人负责。

## 串口连接与格式

USART3：115200、8N1，PD8=STM32 TX、PD9=STM32 RX；与上位机/OpenMV 交叉连接并共地。USART1（PA9/PA10）继续连接底盘驱动板。

命令使用文本，每条以实际 CR、LF 或 CRLF 结束。大小写均可，空格和 Tab 可作分隔。串口助手可直接发送下面的命令，不必加编号。

| 命令 | 动作/含义 | 起点要求 |
| --- | --- | --- |
| BASE_L90 | 底盘从当前朝向左转 90° | BMI 已静止校准、数据和底盘编码器反馈有效、底盘停稳 |
| BASE_R90 | 底盘从当前朝向右转 90° | 同上 |
| YAW_L90 | yaw轴旋转机构：正前方 → 左 90° | 已 ZERO，当前位于正前方 |
| YAW_HOME | yaw轴旋转机构：返回正前方 | 已 ZERO，当前在允许的左右 90°区间附近 |
| YAW_R90 | yaw轴旋转机构：正前方 → 右 90° | 已 ZERO，当前位于正前方 |
| YAW_R180 | yaw轴旋转机构：左 90° → 右 90° | 已 ZERO，当前位于左 90° |
| LIFT 100 | 抬升沿正方向发送 100 个脉冲 | 空闲，无需 ZERO |
| LIFT -100 | 抬升沿反方向发送 100 个脉冲 | 同上 |
| RACK 100 / RACK -100 | 齿条沿正/反方向发送 100 个脉冲 | 同上 |
| SPEED 500 | 后续抬升、齿条共用 500 Hz 脉冲频率 | 空闲时设置 |
| ZERO | 将当前 yaw 位置记为正前方；抬升/齿条显示计数清零 | 空闲，先手动摆正 yaw |
| STOP | 停止底盘和上装运动，清除 yaw 有效参考 | 随时可用；计数继续输出 |
| STATUS | 查询最近动作状态、参考有效性、反馈状态、速度和计数 | 随时可用 |
| REPORT 0 / REPORT 1 | 关闭 / 开启自动计数输出 | 随时可用，不停止当前动作 |
| CAL | 重新执行 BMI 静止校准 | 空闲；整车保持静止 |
| HELP | 显示指令列表 | 随时可用 |

抬升/齿条单次脉冲数范围为 -1000～-1、1～1000，0 不接受。正负号沿用已测试的接线方向：抬升正数 DIR=低，齿条正数 DIR=高。没有固定位置档位、累计行程限位或自动回零；原 RACK_1/2、LIFT_1/2/3 已移除。

SPEED 范围为 16～2000 Hz，重启恢复 200 Hz；ZERO、STOP 不改变已设速度。该速度仅作用于后续步进动作，不改变 yaw PWM 或底盘转速。沿用恒速脉冲，没有加减速曲线；原先反馈的 1500 Hz 带载问题原因仍未确认，本次没有加入猜测补偿。

## 回复与动作互斥

上电输出：0 READY ACTIONS_V2。

例如发送 LIFT 100，先收到 0 BUSY，软件脉冲发送完成后收到 0 DONE；失败返回 0 ERROR 原因。回复都以 CRLF 结束。一次只执行一个动作，不排队；运动期间的新动作、SPEED、ZERO、CAL 返回 ERROR BUSY。yaw 动作完成后保留位置控制，此时可执行下一动作。

如需避免重发造成重复步进，可给运动命令加编号：

~~~text
1 YAW_L90
2 YAW_R180
3 YAW_HOME
4 LIFT 100
5 RACK -100
~~~

逐条发送并等待对应 DONE；示例中的 yaw 需预先手动摆正并 ZERO。

- 编号范围 1～4294967295，新编号递增。上电清空编号历史。
- 仅缓存最近一个已接受的正编号命令；重发相同编号、动作及脉冲参数，只返回原 BUSY/DONE/ERROR，不重复运动。
- 同编号换动作或换脉冲数返回 ID_REUSED；更早编号返回 OLD_ID。
- 因 BUSY 被拒绝的新编号未被占用；可在空闲后重发。通过参数检查但启动失败的编号会缓存错误，处理原因后用新编号重试。
- 无编号命令用 0 回复，每次空闲时收到都会重新执行；不要用无编号重发来判断上一条是否执行。
- 无编号命令不会清除最近正编号记录。辅助命令不加编号。

## yaw 参考与控制

每次上电或 STOP/执行故障后，先手动把 yaw 摆到相对底盘的正前方，再发 ZERO。ZERO 只设参考，不驱动 yaw，不自动寻找机械零点，也没有断电位置记忆。YAW_HOME 才会驱动 yaw 返回保存的正前方。YAW_R90 不包含“先回正”；从左 90°直接到右 90°使用 YAW_R180。

沿用用户已验证左转的方向修正：PC7 低、PC8 高使编码器增加。左 90°相对目标 +725，右 90°目标 -725；从左到右总变化 -1450。左右角度以该计数比例为依据，本次集成尚未烧录复测完整四动作。

控制参数当前为 Kp=4、Ki=0、Kd=0.02，最小 PWM=1200、最大 PWM=4200（TIM8 周期 8400，上限 50%），误差 ±5 计数持续 200 ms 后 DONE。每个 yaw 动作保留 15 s 超时及运动路径约 10°余量的越界/反向检查。动作结束后位置控制保持，STOP 关闭 yaw 控制；步进仍沿用驱动器使能保持设置。

2026-10-07 用户反馈转动慢、没力且遇障碍停止，因此将 Kp 从2提高到4，最大PWM从2500提高到4200；最小PWM、死区及其余控制逻辑不变。左90°起步输出从1450/8400（约17.3%）提高到2900/8400（约34.5%）。这是一档待实车验证的增强参数，并非已完成PID整定或确认硬件力矩充足。若出现明显冲过目标或来回摆动，可先恢复 Kp=2、MAX_PWM=2500。遇障碍仍可能堵转；此程序没有电流/堵转专用检测，15秒动作超时不等同于电机或驱动器过流保护。

## 计数与故障

每 2000 ms 输出一组以 # 开头的状态行，分主循环发送：

~~~text
# t_ms=... yaw_enc=... lift_steps=... rack_steps=...
# yaw_busy=... lift_busy=... rack_busy=... ZERO=... IMU=... ENC=... SPEED=...
# yaw_pwm=.../8400 yaw_ctl_ms=... tx_errors=...
~~~

STATUS 还会触发一次这组输出。以 # 开头的行是遥测，不是 BUSY/DONE 应答。

关闭自动计数请发 `REPORT 0`，回复 `0 REPORT OFF`；恢复发 `REPORT 1`，回复 `0 REPORT ON`，之后每2000ms输出。每条命令仍需换行。重启恢复开启；ZERO/STOP不改变此开关。关闭时仍接收命令、输出 BUSY/DONE/ERROR，`STATUS` 仍主动查询一次状态与计数。不要再注释 `Telemetry();` 或 `RobotActions_Task();`。

用户报告注释 `Telemetry();` 后整车不响应命令、恢复该行后正常，根因尚未定位。当前代码审查和临时关闭输出的主机控制检查未复现；新增串口开关用于在同一份固件内比较，不能据此宣称已修复原故障。可先在静止状态依次发送 `REPORT 0`、`HELP`、`STATUS`、`REPORT 1`，记录每条回复；上位机发送逻辑也不应依赖周期计数到达才允许发送命令。

yaw_enc 来自 TIM2 真实编码器；lift_steps/rack_steps 是累计已发软件脉冲，三者均相对最近 ZERO（未 ZERO 时相对启动读数）。ZERO=1 表示 yaw 的手动参考有效。yaw_pwm 是软件写入的 PWM 值，yaw_ctl_ms 是控制中断累计次数，不是实测引脚波形。

步进 DONE 只证明软件计数达到目标，不证明电机未丢步、未卡住或机构已到某机械位置。STOP 后保留已发部分的计数。上装命令不依赖 BMI 或底盘反馈就绪；底盘动作仍要求这两类反馈有效。

常见错误：NEED_ZERO、YAW_START_POSITION、YAW_RANGE_OR_DIRECTION、YAW_TIMEOUT、STEPS、SPEED、BUSY、IMU_NOT_READY、ENCODERS_NOT_READY、BASE_MOVING、FEEDBACK_LOST、TURN_DIRECTION、TIMEOUT、STEP_INCOMPLETE、RX_LOST、LINE_DISCARDED、TX_LOST。串口接收错误/溢出会停止运动并丢弃残缺行至下一个换行；发送失败也会停止运动并清除 yaw 参考。

## 构建与维护

~~~powershell
cmake --preset Debug
cmake --build --preset Debug
python tests/run_checks.py
~~~

固件输出：build/Debug/counter.elf。VS Code 默认构建任务先配置再构建，烧录任务仍使用原 CMSIS-DAP/OpenOCD 设置。

核心文件：robot_actions.c（命令/动作/状态）、actuator_control.c（yaw PID/步进脉冲）、robot_io.c（串口/底盘驱动）、robot_protocol.c（驱动板反馈解析）、bmi088.c（底盘相对航向）。可调参数集中在 Core/Inc/robot_config.h。

底盘沿用原有相对转弯算法：Kp=6，驱动板速度指令 120～400，角度容差 1°，角速度不超过 2°/s 稳定 200 ms 判完成。BMI088 固定在底盘上，测量底盘自身朝向；与 yaw轴旋转机构分开控制。

CubeMX 配置与目录整理记录见同目录下的 CubeMX与工程整理说明.md。
