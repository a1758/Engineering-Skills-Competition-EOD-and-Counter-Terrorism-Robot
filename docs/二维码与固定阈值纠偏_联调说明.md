# 二维码与轨道纠偏联调说明

## 合入内容

`测试成功的代码/short_long_track_test.py` 的默认纠偏检测已移植自 `correction_only_integration.py`：固定 LAB 阈值、扫描带候选筛选、轨道中心拟合及左右边界拟合。取消原默认算法的边界残差拒绝和自动收缩 L 阈值，保留中心拟合残差检查。保留第二份程序的二维码任务、UART 流式解析、故障保护和完整中心显示。

第一份程序上电即发送纠偏数据；合入版本为整轮路线联调，上电等待命令，不自动开启纠偏。

## 接线与模式

- `OPERATION_MODE = "INTEGRATION"`。
- UART1，115200、8N1；STM32 PD8 → OpenMV P0，PD9 ← P1，双方共地。
- 俯仰 P7：Timer4、50 Hz、500～2500 us、反向映射。二维码逻辑80°，纠偏逻辑180°。
- P9 补光开启，P5 激光关闭。
- RGB565、VGA，图像不镜像、不翻转。

## 整轮流程

1. STM32 启动时可发送多条 READY；任务开始前不会误判重启。
2. 收到 qr 后扫码。首次识别一个有效三位数字任务码，保存任务并发送一次 `finishqr\r\n`。
3. STM32 到纠偏点发送 `rectify\r\n`。
4. OpenMV 切换俯仰，等待700 ms，自动成像调整1500 ms、刷新200 ms；准备期间不发送旧图像测量。
5. 准备完成后按70 ms最小发送周期测量。实际相邻帧间隔须实机检查，STM32要求不超过150 ms。
6. STM32 连续3帧有效后，经执行表 PAUSE 启动后续直行：200指令上限，叠加横移和航向融合。
7. STM32 在行驶期间连续5个新帧满足 |X|≤20 px、|T|≤3°后发送 `finishrectify\r\n`。
8. OpenMV 停止该段视觉输出；STM32保留融合航向偏差并逐步恢复巡航950，继续剩余里程。

## 数据与参数

```text
VERR 1 X T 80 age_ms
VERR 0 0.0 0.0 0 0
```

使用实际CRLF行尾。有效数据必须为有限数，|X|≤320 px、|T|≤15°、age_ms≤150。20 px和3°是完成阈值，不是有效范围。TRACK默认关闭。

- `TRACK_GRAY_LAB = (42, 100, -17, 14, -18, 9)`：固定阈值，按现场轨道标定。
- `DEBUG_MIN_SAMPLES = 4`：至少四条扫描带，覆盖高度至少15%。
- `DEBUG_MAX_FIT_RESIDUAL_QVGA_PX = 15`：中心拟合残差，VGA对应30 px。
- `TRACK_CENTER_OFFSET_QVGA_PX = 15`：VGA参考中心为350 px。
- `LATERAL_SIGN = 1`，X=参考中心−轨道中心；正X请求STM32左移。
- `HEADING_SIGN = -1`，`HEADING_ZERO_DEG = 0`：需实车确认方向和零点。

画面显示参考中心、容差线、轨道边界、中心十字和X/T。视觉日志每秒打印一次；不代表每秒才发送一帧。

## 实机检查

确认启动日志为 `QR_FIXED_LAB_INTEGRATION_V3`。观察有效VERR和实际帧间隔，STM32应打印 `VISION_READY slow_cmd=200` 与后续FORWARD。若不动，读取VISION_STATUS的good、ready、move和wheel；软件指令不能证明电机已经执行。

finishrectify也可能是到站或故障退出，必须同时检查ERROR行。方向正确时误差应总体减小；变大先检查横移和转向符号。故障后重新运行OpenMV并重新启动STM32。
