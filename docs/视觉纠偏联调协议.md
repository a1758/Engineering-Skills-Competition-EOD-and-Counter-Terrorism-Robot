# OpenMV—STM32 视觉纠偏联调协议

版本：V1.0

## 一、用途

陀螺仪纠偏仍不能保证底盘走直时，由 OpenMV 提供视觉误差，STM32 负责底盘运动和四轮速度修正。

OpenMV 不直接控制四个电机，只发送路线识别结果和视觉误差。STM32 负责把误差转换成底盘修正，并负责超时停车。

坐标约定：

- e_y_mm > 0：车体位于路线右侧，需要向左修正。
- e_y_mm < 0：车体位于路线左侧，需要向右修正。
- e_theta_deg > 0：车头相对路线向左偏。
- e_theta_deg < 0：车头相对路线向右偏。
- 横向误差单位为毫米，角度单位为度。

如果 OpenMV 只能得到像素偏差，必须先完成像素到毫米的标定，不能直接把像素值当毫米发送。

## 二、二维码握手

第一段直行完成后，STM32发送：

    qr

OpenMV完成二维码识别后发送：

    finishqr

识别失败时不要发送 finishqr，让 STM32 保持停车。当前等待超时为 30 秒，超时后报告：

    ERROR VISION_TIMEOUT

二维码数据如需调试回传，可发送：

    QRDATA <text>

当前 STM32 只把 finishqr 作为继续路线的信号，QRDATA 仅用于记录。

## 三、视觉纠偏帧

推荐使用一行一帧、空格分隔的 ASCII 格式：

    VERR <valid> <e_y_mm> <e_theta_deg> <quality> <age_ms>

字段：

| 字段 | 含义 |
|---|---|
| valid | 1 表示本帧有效，0 表示无有效路线 |
| e_y_mm | 横向偏差，单位 mm |
| e_theta_deg | 车头相对路线角度偏差，单位 degree |
| quality | 视觉质量，0～100 |
| age_ms | 图像采集到发送的估计延迟，单位 ms |

有效示例：

    VERR 1 18.5 -2.4 92 35

无效示例：

    VERR 0 0.0 0.0 0 0

无效帧不能作为纠偏依据。

## 四、发送要求

OpenMV在车辆运动期间每 50～100 ms 发送一帧，即 10～20 Hz。

要求：

- 始终发送最新值，不发送过期缓存。
- age_ms 建议不超过 150 ms。
- quality < 50 时建议发送 valid=0。
- 路线暂时离开画面时发送 valid=0。
- 不要重复发送旧的有效数据。

## 五、STM32处理规则

STM32使用：

    heading_correction = K_theta * e_theta_deg
    lateral_correction = K_y * e_y_mm

heading_correction 加入旋转修正，lateral_correction 加入横移修正，前进速度仍由 STM32 控制。

建议初始试车参数：

    K_theta = 3.0 command/degree
    K_y = 0.5 command/mm
    视觉纠偏最大值 = 120 command

以上是低速试车初值，不是最终标定值。

| 条件 | STM32动作 |
|---|---|
| valid=1 且 quality>=70 | 正常前进并纠偏 |
| valid=1 且 50<=quality<70 | 降低速度并小幅纠偏 |
| valid=0 持续小于 300 ms | 暂时沿用陀螺仪 |
| valid=0 持续 300～1000 ms | 降速 |
| valid=0 超过 1000 ms | 停车并报告视觉超时 |
| age_ms>300 | 视为无效 |
| 横向偏差超过 100 mm | 停车或重新对准 |
| 角度偏差超过 15 度 | 停车 |

## 六、建议回复

STM32收到视觉数据后可选回复：

    VACK <valid> <sequence>

例如：

    VACK 1 25

如果暂时不实现 VACK，OpenMV仍按固定频率持续发送，不要等待回复后才继续发送。

STM32可提供：

    VISION_STATUS

建议回复当前 valid、横向偏差、角度偏差、质量、数据年龄和超时状态。

## 七、联调步骤

1. 小车静止，确认视觉数据输出稳定。
2. 把车放到路线右侧，确认 e_y_mm 为正。
3. 让车头向左偏，确认 e_theta_deg 为正。
4. 低速直行，先只启用视觉纠偏。
5. 同时记录视觉数据、BMI航向、四轮指令和四轮反馈。
6. 先确认修正方向正确，再逐步增加增益。
7. 直行稳定后再接入完整路线。

符号测试不通过时，先修正坐标符号，不要靠增大参数解决。

## 八、当前路线中的使用方式

当前路线顺序为：

    STM32前进800 mm
    STM32发送 qr
    OpenMV识别二维码
    OpenMV发送 finishqr
    STM32继续后续路线

如果要让第一段直行过程中也使用视觉纠偏，OpenMV需要在运动期间持续发送 VERR。二维码握手负责识别完成，VERR 负责运动纠偏，两者是独立数据。

## 九、安全要求

- 视觉数据超时必须停车。
- 视觉数据无效时不能提高速度。
- STM32必须限制横移和旋转修正最大值。
- OpenMV不能绕过 STM32 的停止和故障保护。
- 视觉纠偏不能替代四轮电机速度闭环。
- 如果编码器反馈与实际运动不一致，仍需校准电机、轮胎和驱动板。

## 十、当前 OpenMV 测试脚本的启停与标定

适用 `qr_correction_with_correction_test.py`。以下是需要 STM32 接入的命令约定，不表示现有固件已经支持。

- 每个需要视觉纠偏的路段，STM32 确认镜头姿态适合该段路线后发送 `correct`，可附 CRLF；OpenMV 开始持续发送按行分帧的 `VERR`。
- 第一次平移完成、停车并确认镜头姿态后，也发送 `correct`，开启后续路段纠偏。二维码完成本身不表示平移完成，OpenMV 不用延时推断到位。
- 停止纠偏发送 `stopcorrect` 或 `finishcorrect`，可附 CRLF；后续路段可再次发送 `correct`。到二维码站发送 `qr` 会暂停纠偏并开始扫码。
- 故障停止纠偏；整轮重测时双方重新初始化。当前 STM32 工程需要实现启停命令发送及 VERR 接收，OpenMV 不会仅凭里程或时间启动。
- 脚本默认 `CORRECTION_CALIBRATED=False`，只发送 `valid=0`。固定相机高度、俯角及视角，完成毫米比例和符号标定后才改成 `True`。
- `MM_PER_QVGA_PIXEL` 表示在脚本使用的底部参考行，每个 QVGA 像素对应的毫米数；VGA 自动按宽度缩放。旧值 `180/220` 是估算，需实测替换。
- 车位于路线右侧时确认横向输出为正；车头左偏时确认角度输出为正。必要时调整 `LATERAL_SIGN`、`HEADING_SIGN`。终端显示的 X/T 可用于未启用有效帧时的检查。
- 本脚本适用于前视双边线。平移后若水平机构转向或改成侧视，必须重新标定对应姿态并使用适合侧视的检测方式，不能直接沿用前视参数。
- `VERR TX` 日志记录帧、数据年龄及实际发送间隔；目标 50～100 ms，超过范围时需降低图像处理耗时，不能把旧结果重发来补频率。
