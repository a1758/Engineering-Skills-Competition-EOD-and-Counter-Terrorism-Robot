# OpenMV → STM32 视觉协议 V2

## 与所提供资料的关系

串口通信协议.xlsx和两份USART PDF描述的是STM32↔四路电机驱动板，不含视觉消息。本协议新增VIS/VCMD/VACK，沿用资料中的ASCII `$...#`分帧方式，加CRC16，需在STM32固件中增加解析。不要将视觉帧直接接到原厂电机板期待其识别。

115200，8数据位，无校验，1停止位，无流控。OpenMV UART1：P0(TX)→STM32独立串口RX，P1(RX)←STM32该串口TX，共地、3.3V TTL。转接板的5V是电源，不是串口信号电平。STM32↔电机板继续使用原有串口；如采用PDF示例的USART2接驱动板，视觉应使用另一可用USART，不要把两个TX并接。STM32的具体串口/引脚应以你的工程配置为准。

main.py默认UART_ENABLE=True、UART_ID=1；若实际接P4/P5，应改UART3。云台和补光配置保持此前状态，不会因启用通信自动驱动。

## 帧结构与校验

`$VIS:字段0,...,字段26*CCCC#`

所有字段为十进制整数，CRC为4位十六进制。没有换行。CRC-16/CCITT-FALSE：poly=0x1021，init=0xFFFF，refin/refout=false，xorout=0。校验范围是ASCII字节，从VIS/VCMD/VACK的首字母到最后一个数据字符，包含冒号和逗号，不包含`$`、`*`、CRC文本、`#`。标准测试向量`123456789`得到0x29B1。

最大允许帧长320字节；STM32接收缓存建议至少384字节，DMA环形缓冲建议512字节或更大。不要直接套用PDF示例的未严格检查长度/字段数量的字符串复制逻辑。

## VIS固定27字段

| 下标 | 字段 | 说明 |
| --- | --- | --- |
| 0 | version | VIS固定2；VCMD/VACK/VEVT仍为1 |
| 1 | seq | 视觉帧号，uint16，65535后回到0；OpenMV重启也从头开始 |
| 2 | mode | 0待机、1巡航、2二维码、3球、4靶、5人质、6黑色桶候选 |
| 3 | flags | 下述位标志，0~255 |
| 4 | reserved | 固定0，不发送球色 |
| 5 | reserved | 固定0，不发送靶色 |
| 6 | reserved | 固定0，不发送形状 |
| 7 | processing_ms | 当前图像识别耗时，ms，非两端同步时钟 |
| 8 | verdict | 0未知/未确认、1对（符合任务）、2错（稳定识别为非任务目标） |
| 9 | cx | 目标包围框中心横坐标，px |
| 10 | cy | 目标包围框中心纵坐标，px |
| 11 | width | 目标包围框宽，px |
| 12 | height | 目标包围框高，px |
| 13 | dx | cx-160，右侧为正 |
| 14 | dy | cy-120，下方为正 |
| 15 | candidate_count | 当前帧候选数量（最大255），调试统计，不代表锁定数量 |
| 16 | track_error | 巡航赛道中心-车辆图像参考点，px，右侧为正 |
| 17 | heading_cdeg | 图像方向偏差×100，右偏为正；123=1.23°，不是实车航向 |
| 18 | left_margin | 图像车辆参考点到左侧路面边缘的距离，px |
| 19 | right_margin | 右侧距离，px |
| 20 | near_left | 近扫描带左边缘横坐标，px |
| 21 | near_right | 近扫描带右边缘横坐标，px |
| 22 | far_left | 远扫描带左边缘横坐标，px |
| 23 | far_right | 远扫描带右边缘横坐标，px |
| 24 | clearance_left_dmm | 完整矩形车身到左边缘最小净空×10，0.1mm，含3mm外廓余量，负数为越界；未标定无数据 |
| 25 | clearance_right_dmm | 右车边净空×10，0.1mm |
| 26 | warning | 0无、1失线、2像素边距不足、3车边净空不足、4过期、5云台稳定等待、6高度/姿态标定或外廓未确认、7赛道物理几何不一致 |

所有不可用的坐标、尺寸、距离、角度字段为**-32768**。有效数值饱和到-32767~32767，换算会舍入。判定未知用0，不使用-32768；任务内容仅保存在OpenMV。Q VGA固定320×240，原点左上；若换分辨率须同时改检测ROI、参考中心和协议约定。

flags按位：bit0=当前结果有效；bit1=连续确认；bit2=云台姿态就绪；bit3=已经保存二维码任务；bit4=当前选择目标符合已保存任务；bit5=巡航停止请求；bit6=数据过期；bit7=毫米净空已标定且可用。

例如`flags & 1`检查有效，`flags & 32`检查停止请求。巡航危险边距时bit0可以为1，但bit5也为1，STM32仍须停车。二维码任务保存在内存，码消失后bit3可保持1，而bit0/1为0。任务只在二维码连续3帧有效时更新。

小球/靶/人质只发送当前选择的一个目标；所有候选仍可在IDE打印字典中查看。有任务时从匹配任务的候选里选择，无任务时仅供调试。bit1/bit4不代表已到抓取距离、已打靶成功或允许直接执行动作。

已验证的小球数据示例（目标匹配，cx=170/cy=100；实际颜色和任务码不在线路上传输）：

`$VIS:2,0,3,31,0,0,0,12,1,170,100,40,40,10,-20,1,-32768,-32768,-32768,-32768,-32768,-32768,-32768,-32768,-32768,-32768,0*6C59#`

## STM32 → OpenMV指令

`$VCMD:1,cmd_seq,command,arg*CCCC#`

| command | arg | 作用 |
| --- | --- | --- |
| 1 | 0~6 | 调试切换对应视觉模式，进入姿态并重置连续确认；比赛使用命令4到位通知 |
| 2 | 0 | 清除已保存任务，准备新一轮比赛 |
| 3 | 0 | Ping查询当前模式 |
| 4 | 到位码 | 底盘停止/动作完成通知，码值详见任务流程对接.md |
| 5 | event_id | 确认收到VEVT事件 |
| 6 | 0 | 桶位对准后允许放下 |
| 7 | 0/1 | 禁用/启用一次圆弧转弯提示 |

## OpenMV激光控制与事件

激光由OpenMV P9输出高低电平控制，STM32负责底盘停车、必要的位置微调及命中成功反馈，不需要直接驱动激光控制线。控制模块支持3V/5V高电平开启；独立额定电压供电、共地，建议控制线加10kΩ下拉。

`$VEVT:1,event_id,action,arg*CCCC#`沿用相同CRC规则，事件持续重发至命令5确认。action3=OpenMV已开启激光，arg为靶位0/1/2；action15=激光瞄准未标定；action11=需底盘微调。完整事件表见任务流程对接.md。

收到事件3仅说明发生过开启动作，不表示当前仍亮或打靶成功。STM32保持停车，实际命中后发命令4、arg50，OpenMV关闭激光并发事件8请求水平机构右转90°；完成后arg51才恢复巡航俯仰。开启条件为靶位到位、任务颜色与位置锁定、姿态稳定及标定窗口满足；目标丢失/偏离、软件超时、模式切换或异常关闭。主循环关断可能因图像处理阻塞延迟。

## 最新路线到位码补充

到位码40=返回第二球位；41=水平机构右180°完成面向桶；42=放球后水平机构左90°完成。50=命中确认；51=打靶后水平机构右90°完成，恢复寻轨并启用拐角观察；52=拐角底盘右90°完成。61=夹人质后水平机构右90°完成，恢复巡航并检测紫区；60=紫区停车完成。球/靶/人质到位码10~12/20~22/30~32还须保证水平机构朝向已完成且底盘停稳。

事件14须圆弧候选及有效毫米边缘净空达到阈值，作为停车请求；事件16为紫色区域稳定识别，请减速并在紫区停车。OpenMV不直接执行转弯或停车；事件16不表示已经到达最终停车点。紫区只能在61后检测，不影响VIS V2的字段布局。详细完整路线见任务流程对接.md。

VIS保留27字段布局及flags；版本升级为2，字段4~6固定0，字段8改为对错判定，没有实时laser_on字段，不能用bit1或事件确认代替激光电平反馈。无需新增未经校验的直接开激光串口指令。单独调试模式切换不会自动建立比赛的TARGET任务阶段。

切换球模式示例：`$VCMD:1,7,1,3*CC20#`。其他指令务必重新计算CRC，不能只改示例数字。

回执：`$VACK:1,cmd_seq,status,mode*CCCC#`。status=0成功、1非法命令/参数、2近期重复序号但内容不同。成功仅代表命令已接受，云台可能仍在移动，须等待VIS的bit2及正确mode。CRC错误/畸形帧静默丢弃，避免针对损坏序号误回执。

STM32建议单条指令等待ACK，500ms未收到时重发相同序号和内容，最多3次；新命令递增cmd_seq。OpenMV缓存最近8条命令回执，相同序号内容直接重放ACK，不再次执行（避免重发RESET清掉刚识别的任务）。重复ACK里的mode是原执行时模式，不作为当前模式状态；当前状态以VIS为准。重启/长时间断线后重新查询并建立流程状态。连续重复设置当前mode不会重复移动云台。

接收支持分段、粘包、噪声、重新遇到`$`同步、96字节指令上限和200ms残帧超时。每轮读取最多128字节，ACK队列上限4；队列满时不执行新命令，STM32通过超时重试。

## STM32解析和控制要求

逐字节/分段接收：遇`$`重新开始，遇`#`结束；缓冲满时丢帧，等待下一`$`。在主循环任务中先验证CRC，再验证VIS版本2、27个字段、数值范围与mode。禁止不限制长度的strcpy，禁止在UART中断中做运动控制。用完整解析后的临时结构原子更新最新结果，不能让控制环读到半帧。

视觉控制前确认：消息是VIS，mode符合当前动作，bit0/bit2为1且bit6为0。巡航还须bit5=0，所有使用字段都不是-32768；只有bit7=1才能用毫米净空。抓取/瞄准需要bit1/bit3/bit4及STM32自己的位置/距离/动作条件。非TRACK模式下单摄像头无法持续看路，车体应停车。

使用STM32本地收到**完整CRC有效且符合当前模式**帧的时刻计新鲜度；ACK、CRC坏帧和错误模式帧不刷新运动看门狗。每帧都检查valid，不能只检查上一次有效帧。接收超时初始建议200ms，最终按实际帧率、车速和制动距离确定；视觉丢失/云台运动/过期/停止请求时进入STM32停车流程。OpenMV识别耗时也受200ms预算约束，但这不代替STM32看门狗。

发送周期目标50ms，实际受采图/识别时间约束。发送采用最新帧替换旧待发帧，ACK优先，支持UART部分写入；部分帧超过100ms停止继续发送，下一帧`$`重新同步。不能宣称固定20Hz，须上板测量。串口发送异常计入tx_errors；接收CRC/格式等错误计入bad_frames（可在IDE调试）。

## 电机板资料中需注意的事项

OpenMV不发送spd/pwm或初始化电机参数。STM32按当前车体运动学和视觉偏差决定电机指令，驱动板原有编码器MAll/MTEP/MSPD消息仍按原协议处理。

轮径已知80mm，若需要配置驱动板，由STM32按PDF的`$wdiameter:80#`实现。不得直接把视觉像素误差写入轮速；轴距200mm、半轮距82.5mm用于运动学，不能替代实测车身半宽。

资料有两处明显不一致：xlsx对mline的备注混用了减速比，PDF将mline定义为霍尔编码器线数，mphase定义为减速比；pwm示例误写成spd，真正PWM指令前缀应为pwm。最终以实际驱动板固件验证结果为准，本次不改驱动板配置。

## 验证结果

本地check_serial.py验证了标准CRC向量、27字段、符号/单位、无效/过期标志、分段收包、粘包恢复、重复模式指令、ACK、CRC损坏、超长帧、部分发送及收发超时。check_logic.py原识别逻辑检查也通过。未接入真实OpenMV/STM32串口，尚须上板检查固件UART接口、接线、吞吐和接收解析。
