# STM32底盘控制移交说明

用途：将旧K230直接控制底盘的资料移交给STM32负责人，配合当前OpenMV视觉辅助。依据k230_1_line_final.py的实际常量及函数调用整理。历史参数不是新底盘闭环控制的标定结果。

## 控制职责与接线

STM32负责所有底盘直行、平移、转向、减速、停车及编码器/BMI反馈；OpenMV负责识别、视觉偏差与任务事件。OpenMV不直接发送驱动板轮速命令。

STM32 USART1 PA9/PA10连接驱动板；USART3 PD8 TX接OpenMV P0 RX、PD9 RX接OpenMV P1 TX，115200、8N1，共地。UART1/USART3用于上层消息，驱动板串口是另外一条链路，不能混用其格式。

车体参考：保守外廓240×240mm，轮径80mm；用户提供KINE_WHEELBASE=200mm、KINE_AXLE_HALF=82.5mm。轴距、半轮距与车体外廓不是同一尺寸，运动学中的实际轮心距应由STM32负责人核对定义和实测。轨道宽按300mm估算，居中时左右各30mm；另加每侧3mm外廓 allowance后约27mm。这只是平直且车身平行轨道时的几何余量，转弯和偏航不能沿用。

## 旧代码驱动板协议

ASCII：`$spd:M1,M2,M3,M4#`，无CRLF，无本文额外CRC。旧程序UART2为115200。轮速数值的单位、允许范围和反馈格式需要结合驱动板说明另行确认；900不是900mm/s。

|编号|旧代码定义|
|---|---|
|M1|左前|
|M2|左后|
|M3|右前|
|M4|右后|

|动作|旧代码实际输出示例|
|---|---|
|停车|`$spd:0,0,0,0#`|
|前进，历史左右比例|`$spd:-900,-900,-918,-918#`|
|左平移|`$spd:900,-900,-900,900#`|
|代码名为右转90°的函数|`$spd:900,900,-900,-900#`|
|最后长直行，历史右侧0.970比例|`$spd:-900,-900,-873,-873#`|

旋转函数的文字注释声称相反符号且340ms，但实际函数输出如表，常量ROTATE90_MS=900ms。方向必须架空低速验证，不能根据过期注释接入。左右轮比例修正方向的注释也须实测，不能认定让右轮更快必然纠正某个方向。

旧代码直行/平移每100ms发送轮速，转向每50ms发送；按运行时间结束并发送一次零速。新STM32应按照驱动板刷新/失联要求持续控制，并用反馈确认停车，不能只依赖一次零速写成功。

## 距离与转向控制建议

旧代码CAR_SPEED_MM_S=359.4、SIDE_SPEED_MM_S=311.4来自指令300时119.8/103.8mm/s按三倍估算，未证明指令900时实测成立。旧距离通过distance/speed换算时间，是开环距离，不是编码器闭环。

STM32应使用实测轮径、编码器每圈计数和反馈刷新率，将目标直行/平移距离换算成反馈目标。麦轮横移的打滑、减速带和载荷变化需单独标定。转向优先用现有BASE_R90/BASE_L90的BMI/编码器反馈，替代旧900ms定时转向。控制主循环保持非阻塞，持续处理视觉、串口与反馈。

不要直接把旧900指令移植进现有BASE_*实现；动作说明中的120～400是另一套控制参数，需要统一单位、允许范围和实际车速。

## OpenMV与STM32握手

完整消息格式、CRC、VIS V3字段和到站码见同目录路线视觉双向接口.md。现有ACTIONS_V2说明未提供直行/平移/视觉闭环，STM32必须新增这些功能。

1. OpenMV初始化后发送一次`start\r\n`，STM32收到后验证反馈和任务状态，开始首段；start需在STM32新增实现。
2. STM32发送VCMD command3 PING，收到VACK后进入视觉数据接收。
3. 到二维码位置停稳后发送command4,arg1；等事件1（二维码存好）及事件17（该段参考就绪），分别ACK，才开始平移。
4. 每段按目标距离行驶，叠加视觉修正；真正停稳后再报对应到站码。云台命令DONE不能代替底盘停稳。
5. 小球/靶子/人质到站后等正确、错误或未知处理事件。正确夹取完成后继续指定任务；错误去下一位置；未知保持停车重试，不能当作错误。
6. 拐角事件14、紫区事件16/19请求停车/减速，最终实际停车由STM32反馈确认。

VEVT事件按ID去重，ACK表示已接管，不表示动作完成；重复事件不得重复执行运动。轮速命令与视觉消息各用各自协议，不把VIS帧转发给电机板。

## 视觉辅助纠偏

VIS V3字段16为图像偏差，17为图像倾角×100，27为类型：0CENTER、1FRONT、2SIDE，28为路线段。前缘/侧缘模式用边缘y与该段参考y之差；CENTER用轨道中心相对画面参考偏差。它们不是统一的物理横向距离，也不是IMU航向角。

STM32每段明确相机朝向、主运动轴、距离修正轴和偏航修正符号。麦轮直行时可小幅横移纠正横向偏差，平移时可小幅前后移动保持前缘距离；根据IMU和图像倾角辅助稳住姿态。先分别测试距离纠偏和姿态纠偏，再组合。控制增益、死区、滤波、速度上限、加减速需要现场标定，本文不给未经验证的PID数值。

只使用有效、姿态就绪、非过期且非停车要求的数据。无效值-32768不可进入控制。到站识别、云台旋转、参考学习期间停车；持续缺少有效消息超过200ms应减速/停车。拐角不要继续用直线中心控制强行穿过。编码器/IMU丢失也须停止相应闭环动作。

## 实车交付测试

- 架空低速逐个测M1..M4轮号和正负方向，再测前进、左平移、左右转，不先跑整条路线。
- 用尺测直行/横移实际距离、车速、停止距离；区分空载、抓球/人质负载和减速带。
- 核对首段二维码680mm及每个停车点；历史距离逐段修订，记录实际配置版本。
- 固定安全净空后逐段标定OpenMV参考，低速左右扰动验证纠偏符号、限幅和恢复能力。
- 测重复事件、分段串口包、错误CRC、断线、丢边、BMI/编码器掉线的停车行为。
- 最后串联路线，记录路线段、里程、到站码、事件ID、识别结果、云台命令和DONE。
