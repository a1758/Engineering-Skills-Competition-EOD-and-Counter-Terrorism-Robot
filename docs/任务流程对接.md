# 半固定底盘路线与OpenMV视觉流程

## 最新路线（本节及下方修订后的码表为准）

1. 初始俯视巡航；STM32行驶后停车，发送到位码1，OpenMV解析并保存二维码，事件1只报告保存完成。
2. STM32执行**平移→直行→直行→平移→直行→暂停→底盘右转90°→直行到第一个球位→暂停**。这些距离和顺序属于STM32半固定路线，OpenMV不以时间推断到位。
3. STM32将云台夹爪水平机构旋转90°，完成且底盘停止后发送10。OpenMV俯仰转BALL，按任务判断对错；错则事件2换位，换位完成发11/12。对且对准后夹取。
4. 事件4表示夹取脉冲等待完成。STM32返回第二个球位并停车，发40；事件6请求**水平机构右转180°**，完成后发41。OpenMV俯仰转BIN识别黑桶，STM32确认对准后命令6允许放下。
5. 事件7表示放下动作等待完成，请STM32将**水平机构左转90°**；完成后发42，OpenMV恢复TRACK俯仰，视觉辅助走长轨道。
6. 到首靶停车，STM32水平机构左转90°，完成后发20；后续靶发21/22。OpenMV正视识别任务靶并控制P9激光，错则换位。STM32确认命中发50，事件8请求水平机构右转90°；完成发51，OpenMV恢复TRACK并开启拐角观察。
7. 连续三帧中心轮廓弯曲后，且标定毫米净空达到CORNER_STOP_CLEARANCE_MM（初值18mm），事件14请求暂停。STM32停车后**底盘右转90°并直行**，发52恢复普通巡航。没有有效地面标定时只有IDE的corner_candidate，不产生基于毫米的转弯请求；失线及净空不足仍由VIS停车标志处理。
8. 到首个人质位停车，STM32水平机构左转90°，完成发30；其他位置发31/32。OpenMV正视人质，对错判断和夹取同前。
9. 事件5表示人质夹取动作等待完成，请STM32将水平机构右转90°；完成发61，OpenMV恢复TRACK、开启紫色终点检测并辅助直行。
10. 连续稳定看到紫色区域后事件16请求减速并在紫区停车；STM32决定车速和最终停车点，停稳发60，OpenMV事件9结束。紫色出现不等于已完全进入终点，不能由摄像头直接宣布停车完成。

OpenMV只控制P8俯仰、P7夹爪和P9激光。水平机构旋转与底盘旋转是两个不同动作，都由STM32控制。每个球/靶/人质到位码表示底盘停稳且水平机构转向已完成。夹取后等待水平回正时使用IDLE，不输出可用于行驶的轨道结果。POSE_US第二个值仍须标定，所有初值1500us不能认为已对应指定视角。

补光暂不处理，LIGHT_PIN=None，硬件P7冲突须自行隔离。PURPLE_LAB、PURPLE_ROI及PURPLE_MIN_PIXELS为待现场标定值，终点检测仅在人质夹取及水平回正之后启用，避免其他紫色物体提前结束任务。

本版main.py控制视觉、P7夹爪、P8俯仰和P9激光。STM32负责底盘的所有平移、直行、旋转、距离及打靶成功反馈。补光LIGHT_PIN=None；必须拔下或隔离补光板P7连接，否则夹爪PWM仍会控制LED。

启用前：GIMBAL_ENABLE=True；标定CLAW_OPEN_US/CLOSE_US、SERVO_LIMIT_US，以及POSE_US各模式第二个数（俯仰脉宽）。POSE_US第一个数仅保留旧格式，不再改变夹爪。所有视角当前1500us是占位，并非已标定向下/正视角度。AUTO_GRIP_CALIBRATED默认False，标定夹爪和ALIGN_WINDOWS后才改True；否则识别到目标会返回事件12，不自动闭爪。启动不会强制打开夹爪，开始抓取前须确保机械夹爪已打开。定时闭爪完成只代表脉冲动作等待结束，不是传感器验证夹持成功。

VIS升级为版本2，保留27字段及CRC16；字段4~6固定0、字段8仅输出对错。VCMD/VACK/VEVT仍为版本1。新增VEVT事件帧：`$VEVT:1,event_id,action,arg*CRC#`。事件周期重复，STM32收到后用命令5确认event_id；确认仅表示接收请求，实际到位另发命令4。不要重复执行同一event_id。新增mode6=BIN黑色桶候选，旧模式0~5不变。

VCMD仍是`VCMD:1,seq,command,arg`：

|command|arg|作用|
|---|---|---|
|4|0|底盘巡航；摄像头回TRACK姿态|
|4|1|二维码停车到位，启动二维码解析|
|4|10/11/12|第1/2/3个球位停车到位，启动BALL|
|4|20/21/22|第1/2/3个靶位转向并停车到位，启动TARGET|
|4|30/31/32|第1/2/3个人质位停车到位，启动HOSTAGE|
|4|40|排爆抓取后已返回第二球位，IDLE等待水平机构右180°|
|4|41|水平机构右180°完成、面向桶且底盘停止，启动BIN|
|4|42|放球后水平机构左90°完成，恢复TRACK|
|4|50|确认命中，关闭激光，请求水平机构右90°|
|4|51|打靶后水平机构右90°完成，恢复TRACK并观察拐角|
|4|52|拐角处底盘右90°完成，开始直行人质路线，关闭该次拐角观察|
|4|61|夹人质后水平机构右90°完成，恢复TRACK并启用紫区检测|
|4|60|已抵达终点，IDLE|
|5|event_id|确认已接收事件，停止重复发送该事件|
|6|0|桶位对准后允许放下，须当前有稳定黑色候选且夹爪已标定|
|7|0/1|关闭/开启一次圆弧转弯提示，仅在预定路段开启|

原命令1切模式仅供单独调试，比赛流程使用命令4，避免视觉模式和任务阶段不一致。命令2清任务同时重置流程，不要在夹持物品时使用，软件清状态不会自行打开夹爪。命令3仍是Ping。

|action|含义及STM32响应|
|---|---|
|1|二维码确认，arg固定0；任务内容仅OpenMV保存；走半固定平移/直行路线，到第一个球位发10|
|2|当前位置稳定识别为非任务目标，arg下一候选位置0/1/2；STM32换位后通知对应到位码|
|3|OpenMV已开启P9激光，arg靶位置；不表示命中成功，STM32确认目标动作成功后发50|
|4|球抓取脉冲完成，arg1；STM32无论在哪个球位都返回第二球位，完成后发40|
|5|人质抓取脉冲完成；STM32水平机构右90°，完成发61再直行终点|
|6|第二球位已到，请STM32水平机构右180°；完成发41|
|7|桶位开爪等待完成；STM32水平机构左90°，完成发42后进入长轨道|
|8|命中确认，STM32水平机构右90°，完成发51后恢复巡航|
|9|终点到达，任务结束|
|10|三个位置均识别为非任务目标；停车报告失败，排爆区可由STM32回第二球位，不能假装已抓取|
|11|目标匹配但不在抓取窗口，请微调；VIS含cx/cy，调整停车后重发同一到位码（新命令序号）|
|12|夹爪或抓取窗口未标定，需现场标定后重新运行|
|13|识别超时/未知/多个候选，停车重试；不能解释为颜色或形状不匹配|
|14|连续弯曲候选且毫米净空达到阈值，请求停车核验；STM32底盘右90°并进入人质路线，发52|
|15|激光瞄准未标定，停车标定LASER_AIM_WINDOW并开启LASER_AIM_CALIBRATED|
|16|人质返回路段稳定看到紫区，请STM32减速并在紫区停车；停稳发60|

激光模块控制线接P9，独立额定电压供电，与OpenMV共地。高电平开启，支持3V/5V控制。建议P9到GND加10k下拉使复位期间关闭。LASER_AIM_CALIBRATED默认False，瞄准窗口(160,120,4,4)是待实测值，不能认为靶心出现在图像中心时激光就命中。标定后，TARGET停车到位、任务色及位置连续确认、瞄准窗口满足才开启，初始LASER_ON_MS=500ms；目标丢失/偏离、模式变化或异常关闭。软件关断在图像处理前后检查，处理阻塞可能使实际亮灯时间超过设定值，严格定时需独立硬件截止或后续定时器实现。不会因为超时就自动重开，也不会把激光开启当作打靶成功。

抓取方案已获用户同意，仍需标定实物脉宽及窗口；AUTO_GRIP_CALIBRATED不是方案批准开关，必须完成实测才能开启。

程序仅当一个已知候选连续稳定且符合任务、图像坐标位于抓取窗口后闭爪。不匹配的位置会记录，选择尚未扫描位置；三个均不匹配返回失败。若ROI里同时看到多个球/靶/人质输出超时重试，须限制ROI或逐位置近距离观察，不能任取大色块触发夹爪。

抓取方案供审核：先固定停车点和俯仰角，实测夹爪能够抓取时目标在图像中的位置与大小，填ALIGN_WINDOWS。此方案输出二维坐标给STM32微调，没有三维解算；人质/球是离地立体物体，不能直接套地面GROUND_H获得真实距离。若位置变化大，后续增加目标尺寸测距/相机内参和机械映射。当前只检查最小框宽，不保证抓取深度；须通过实测窗口与固定停车距离保证。

桶检测目前为暗色块候选，黑色背景/台面也可能命中；必须让桶位ROI排除背景，由STM32停车对准并显式命令6后才开爪，不自动因黑色块放下。桶位POSE_US[BIN]应标定为合适俯视角。

轨道纠偏继续VIS16~25。侧向平移/倒车时前向镜头不能保证对应运动方向都在视野内，STM32须使用路线/里程计低速控制，不把TRACK有效等同于横移安全。固定边距毫米计算仍须匹配高度/俯角地面标定。转弯提示采用三扫描带中心曲率趋势，是保守候选，需要实图标定，急弯看不到双边时仍会失线停车，不能依赖圆弧提示一定出现。

确认抓取后事件不自动执行完整路线；STM32依次确认事件、执行底盘动作、回传停车到位。程序通过P9控制激光，不发送电机速度命令，也不用延时假装底盘到位。事件3表示激光已开启，收到事件时激光可能已因超时或丢失目标关闭；它不是实时激光状态，也不是命中证明。

STM32只需处理匹配判定和流程事件，不接收或比较颜色/形状。VIS verdict=1表示识别正确，不是夹取完成；收到事件4（球）或5（人质）后才进入后续路线。verdict=2及事件2请求下一位置；verdict=0和事件13代表未知/超时，应停留重试，不能当作错。二维码事件1只通知任务已保存。坐标及轨道字段继续用于微调和纠偏。
