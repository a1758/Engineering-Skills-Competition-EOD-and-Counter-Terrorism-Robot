# 视觉纠偏方向独立测试

## V7 当前版本：先航向、再X，连续5帧达标后前进

VisionTest标识 `VISION_TARGET_TEST_V7_SEQUENTIAL`。上电停稳发送rectify，连续3帧有效VERR后开始停车纠偏，前进分量始终为0。优先旋转底盘使T进入±3°，然后横移使X进入±20px；横移期间T再次超标则优先恢复航向。旋转指令−1.5×T、横移指令0.8×X，各限幅±60，符号仍需实车验证。

连续5个新鲜有效VERR同时满足两项死区，并确认底盘停稳后，发送 `finishrectify\r\n`（保留现有OpenMV完成词，用户所说finish对应此消息），以此时BMI航向作为直行参考。无效帧、过期或帧间隔超过150ms重置达标计数，同一帧不重复计数。纠偏阶段不进行T/BMI航向融合。

随后从纠偏完成的位置前进1650 mm，按现有加减速恢复巡航950（驱动指令单位，不是mm/s），到站停车、yaw左90°、target、11/22/33、finishtarget和1秒激光沿用V6。等待初始有效帧不设超时；开始纠偏后15秒总超时，持续1秒无有效帧停车报错。STOP与故障取消流程、关闭激光。仅VisionTest改变纠偏流程。

编译通过，尚未烧录或实车确认方向；下文V6及更早为历史流程。

## V6 当前版本：1650 mm + 打靶

标识 `VISION_TARGET_TEST_V6_1650`，烧录 `build/VisionTest/counter.elf`。沿用底盘90°转弯后同一套CORRECT，纠偏及后续直行共1650 mm。到位停稳后yaw左90°，发送一次 `target\r\n`。OpenMV负责80°云台姿态和任务颜色识别，STM32不修改OpenMV程序。

收到 `11` 不移动；收到 `22` 或 `33` 均按当前明确要求前进55 mm，驱动巡航指令上限100（不是mm/s），保留编码器距离、航向、减速及停稳检查。支持两位消息直接发送或带CRLF，错阶段和重复消息不重复运动。识别等待30秒超时报错停车。

选定位置停稳后发送 `finishtarget\r\n`，随后PE2激光控制输出置高，暂保持1000 ms后置低，最终DONE ROUTE。STOP、反馈故障或运动失败关闭激光并取消流程。激光电平和照射时间需实机确认。当前尚未实现打完后的补走到第三靶位：22/33同为55 mm与三个靶位间距含义仍需明确，112233不作为六次打靶任务序列处理。

上电前手动摆正yaw；测试不执行额外底盘90°转弯。下文V5及更早为历史版本。

## V5：视觉纠偏到第一靶位（1300 mm）

本版直接复用正式路线底盘右转90°后CORRECT的实现，不另写纠偏控制器：连续3帧有效VERR启动、边前进边做X横移及T/BMI航向融合、连续10帧同时满足±20px和±3°后发送finishrectify并恢复巡航。速度、符号、融合与失联保护均读取同一robot_route_config.h；当前慢速指令100、巡航950。测试不额外执行一次底盘90°转弯，摆放在纠偏起点即可。

当前 VisionTest 标识为 `VISION_TARGET_TEST_V5_1300`，烧录文件为 `build/VisionTest/counter.elf`。上电不执行前置路线或齿条动作，停车发送 `rectify`，收到连续3帧有效 VERR 后开始视觉辅助直行。该段总距离设为1300 mm，包含慢速纠偏时走过的距离；连续10帧达标后发送 `finishrectify` 并恢复巡航，走完剩余路程。

到第一靶位停稳后，yaw轴旋转机构执行左90°，随后发送一次 `target\r\n` 并保持停车等待。上电前须手动将yaw摆正，上电参考不代表机械自动回零。当前本版仅接通到第一靶位和target通知，尚未处理11/22/33、finishtarget或自动激光动作。STOP取消后续动作。正式路线与BallTest距离保持原配置。

注意：沿用原控制逻辑，到站即使视觉未达标也会退出纠偏；1300 mm不是在finishrectify之后重新计算的距离。编译通过，未烧录验证。下文V4及更早内容为历史版本。

## V3 当前测试流程

当前烧录文件为build/VisionTest/counter.elf，测试标识VISION_DIRECTION_TEST_V3_SLOW_ROUTE。本节取代下文V2在纠偏点等待手动测试的流程。

上电执行原路线及二维码握手；到CORRECT自动发送rectify，无限等待连续3帧有效VERR，随后跳过原PAUSE立即启动后续FORWARD，以200指令上限边走边根据X/T纠偏。无需发送TEST_X/TEST_T。此自动路线纠偏不受500ms点动限制；连续10帧同时满足|X|≤20px和|T|≤3°才发送finishrectify，并恢复原巡航950完成剩余距离。里程不清零，融合航向偏差保留。路线表、距离及正式Debug/Release参数未改。

失联和运动故障保护保留；到站未达标仍按此前约定退出纠偏并进入下一任务。只取消自动路线中的500ms点动方式，不代表失联后仍无限移动，也未加入误差增大时自动反转方向。该测试沿用当前正式视觉横移符号（左移指令=−0.8×X）。下文SIGN只用于路线空闲后的手动单轴点动，不修改自动路线纠偏符号。

主机模拟已验证实际路线、无限等待、3帧启动时跳过暂停、超过500ms仍慢速运行、9帧不结束、10帧结束并加速。构建通过，尚未实车验证。

烧录 `build/VisionTest/counter.elf`，测试标识 `0 READY VISION_DIRECTION_TEST_V2_ROUTE`。本版上电自动执行当前正式路线到第一个CORRECT，包含原二维码握手及配置的上装准备动作；距离直接复用robot_fixed_route.h，未另写一套数值。到CORRECT停车并回复 `0 DONE TEST_ROUTE_READY`，等待TEST_X/TEST_T，暂不执行后续PAUSE/FORWARD/GLOBULE。正式Debug/Release功能及参数不变。

## 横移测试

1. 上电等待BMI校准和底盘反馈，车辆按原路线行驶，OpenMV正常处理qr并回复finishqr。收到DONE TEST_ROUTE_READY后开始方向测试，保证轨道两侧可见。
2. 发送 `SIGN 1`，再发送 `TEST_X`。
3. STM32发送rectify，无限等待连续3帧有效数据；随后最多输出500ms单通道横移，前进和旋转均为0，再自动停车并发送finishrectify。
4. 比较测试前后|X|。减小表示该符号合适，增大则下一次发送 `SIGN -1` 后重复TEST_X。每次需重新发TEST_X，不自动重启。

## 旋转测试

发送 `SIGN -1`，再发送 `TEST_T`。测试只旋转，前进和横移均为0；同样连续3帧启动、500ms自动停止。观察|T|是否减小；若增大，下次换SIGN 1。X/T共用当前SIGN设置，每次切换轴前明确设定SIGN。

## 输出及调速

每250ms输出VTEST，含轴、就绪、有效性、X/T、符号、限幅、左移/左转指令和四轮软件指令。axis=1为X，axis=2为T，axis=0为空闲。左移指令正表示左移，左转指令正表示左转；映射为现有麦轮四轮编号。

默认LIMIT=60，X增益0.8、T增益1.5；这些是测试试调值，不是已验证的机械起动速度。如果指令非零仍不动，可空闲时先发 `LIMIT 120`，必要时再发 `LIMIT 200`。LIMIT只是上限，不会把较小指令自动提升到该值；例如T=6°时旋转指令仍为9。需要更强输出时应先记录日志，再调整测试增益，不能把不动当作符号正确。

有效数据要求valid=1、quality≥50、age≤150ms及有限X/T，相邻有效帧≤150ms。无效或帧过期立即停止输出。启动后500ms脉冲期限不会因失效延长。STOP立即停止测试并退出视觉；后续缓冲VERR不会重启动作。反馈丢失或通信接收丢失也停止。

方向测试阶段不包含BMI视觉融合、固定右移补偿、编码器横向纠偏或自动直行，也不以10帧达标判定任务完成；到纠偏点前的路线保留正式控制。测试完成后再烧录正式Debug固件。

构建：`cmake --preset VisionTest`，`cmake --build --preset VisionTest`。主机模拟覆盖上电空闲、3帧启动、X/T独立轮速混合、SIGN反转、500ms停止、无效数据和STOP；实际方向和负载需实车验证。
